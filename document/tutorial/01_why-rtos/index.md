# 为什么需要 RTOS

这是整套教程的**定位章**:在动手搭环境、写第一个任务之前,先讲清楚我们到底为什么要用一个 RTOS——`main` 里那个 `while(1)` 从什么时候开始变得不够用,RTOS 凭什么能解,以及同样重要的,**它解不了什么**。这一章是纯概念,没有 demo,整段论述收在一篇正文里。

## TL;DR

| 问题 | 一句话结论 |
|------|-----------|
| super-loop 的致命伤 | **串行阻塞**:一件慢事拖住整条循环,中断+状态机能撑一阵但活动一多就失控 |
| RTOS 真正卖什么 | 不是"快"而是**可预测**——把活动拆成任务、用优先级抢占保证高优先级事件的响应上界 |
| 什么时候该上 RTOS | 独立活动多、要安全通信/共享、要延迟上界;反之极简且 RAM 紧就继续裸机 |
| FreeRTOS 是什么 | 嵌入式事实标准的轻量**内核**(只管调度/同步),用 POSIX port 搬到 PC 上学机制 |
| host 模拟的代价 | **时序不可信**——PC 是分时系统,测出的延迟/切换耗时不能推断真硬件 |
| 教学边界 | 专注**内核机制**(跨平台一致);实时性、中断延迟、功耗明确划在边界外 |
